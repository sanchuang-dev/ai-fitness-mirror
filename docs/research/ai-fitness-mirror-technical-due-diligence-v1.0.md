# 智能健身镜：现成 AI 模型技术尽调与研发决策报告

**综合版 v1.0 · 2026-11-17 · 内部立项评审材料，不构成投资批准**

> 研究范围：第三方健身课程接入、实时人体姿态识别、动作计数、动作幅度与节奏、有限且可解释的姿态偏差提示。优先复用现成预训练模型，不自行训练或微调。
>
> 硬性边界：原有 Android 11 无摄像头健身镜不参与本项目的测试、改造、适配或验收。新产品不绑定该旧设备，也不预先绑定某个操作系统或芯片。

## 1. 执行摘要

**建议管理层只批准 G1「免训练模型与动作评价专项 POC」的有上限预算，不立即批准整机量产研发。**

DSH 已在 Mac mini M2 / 8GB 上运行 MediaPipe 姿态模型，并提交原始 JSON、测试方法和脚本。现有证据支持“预训练人体姿态模型可以直接复用”，但尚未证明动作计数准确率，也未证明低成本 ARM 整机可以稳定运行。

建议的 MVP 技术方向：

- MediaPipe Pose Landmarker Lite / Full 作为姿态估计基线；
- 课程动作时间轴优先驱动当前动作，不要求系统每一帧都重新猜动作类别；
- 以动作状态机、关节角、幅度、节奏和经过标定的模板规则完成首期反馈；
- 终端负责实时姿态推理和反馈；服务端负责课程离线解析、动作模板、版本管理；
- 默认不把用户视频逐帧上传云端；
- G1 阶段不输出百分制“动作标准度分数”，无法可靠判断时明确拒判。

DSH 专项 POC 估算为 **42 人日、约 4–5 周**，仅覆盖三动作算法规则、数据标注和评测，不包含完整 H5、整机开发、量产或全部课程商业接入。[DSH-POC][DSH-README]

## 2. 项目背景与尚未取得的前置资料

第三方健身服务商宣称提供大量课程，公司希望用户在镜前跟练时获得动作次数、幅度、节奏和有限姿态提示。当前尚未取得：

- 真实课程目录、样课和课程视频访问方式；
- 动作名称、动作词表、动作起止时间轴；
- 教学示范片段、动作变式及推荐摄像头角度；
- 课程播放授权以外的算法分析、骨架提取和衍生模板授权；
- 目标用户、销售场景、目标售价、预计出货量和整机 BOM 上限；
- 新主板、摄像头、ODM/板厂 SDK 及其商业分发条款。

因此，“课程很多”不能直接推导为“动作覆盖很多”，也不能直接推导为“每节课都能评分”。

## 3. 能力边界：人体识别不等于健身教练

完整运行链路可拆为：

1. 摄像头采集用户画面；
2. 姿态模型识别肩、肘、髋、膝、踝等人体关键点；
3. 对关键点做置信度门控、平滑和归一化；
4. 根据课程时间轴确定当前动作及阶段；
5. 使用动作状态机、关节角度、幅度和节奏规则判断动作周期；
6. 在有证据时给出有限姿态提示；
7. 低置信度、遮挡或视角不适用时拒绝评分。

| 能力 | 现成模型可复用程度 | 仍需自行完成 |
|---|---|---|
| 人体姿态估计 | 高 | 摄像头接入、运行时、机位与性能适配 |
| 动作分类 | 部分可复用 | 若有课程时间轴，可降低通用分类需求 |
| 动作计数 | 可复用方法与模型组件 | 按动作标定规则、滤波和真值评测 |
| 动作质量评价 | 尚无足够证据支持通用开箱即用方案 | 专业评价标准、参考模板、可解释规则和拒判 |
| 课程接入 | 取决于服务商数据 | 时间轴同步、动作 ID、授权和模板版本 |

**关键原则：姿态检测成功不等于计数正确；骨架相似度不等于动作标准度。** DTW 等时序方法可以对齐速度不同的动作序列，但距离值不能直接解释成百分制成绩。

## 4. 模型候选与推荐

| 候选 | 当前判断 | 用途与限制 |
|---|---|---|
| MediaPipe Pose Landmarker Lite / Full | 首选基线 | 已有 M2 CPU 原始测试记录；不是目标 ARM 实测 |
| MoveNet Lightning / Thunder | Web / TFLite 备选 | 需按目标浏览器和芯片复测 |
| RTMPose-t / s | 精度与部署对照 | DSH 报告提及 ONNX 性能，但当前原始 JSON 未包含对应独立结果 |
| RepNet | 周期计数研究对照 | 不作为首期主力 |
| PoseC3D / ST-GCN++ | 骨架时序动作分类研究候选 | 训练集类别与目标健身动作是否匹配仍需核实 |
| PoseConv3D-PT | 待复核研究线索 | 此前提及的原型数量不代表真实课程覆盖率；本轮未完成独立课程评测 |
| Pozify Exercise Router | 有限动作分类参考 | 动作范围与商用许可需进一步核实 |
| ViTPose / Sapiens | 较重模型或离线对照 | 不作为低成本端侧首选 |

本轮公开候选中，**尚未找到同时具备可直接加载权重、可靠健身质量评价证据、广泛动作覆盖和明确商用授权的万能评分模型**。这是本轮尽调范围内的结论，不代表整个市场绝对不存在商业 SDK。

商用前必须分别核对模型代码、权重、训练数据、推理框架、第三方课程及衍生动作模板的授权。开源代码不自动意味着所有模型权重和内容均可商用。

| 测试 | p50 | p95 | 其他记录 |

| Lite IMAGE，1000×667 | 19.95 ms | 27.87 ms | 60 次测量 |

### 5.3 三段公开视频记录

| 视频 / 模型 | 帧数 | 姿态检测率 | p50 / p95 | 稳健规则计数 |
|---|---:|---:|---:|---:|
| ex_0006 / Lite | 4,874 | 98.9% | 15.13 / 47.82 ms | 20 |
| ex_0006 / Full | 4,874 | 98.9% | 25.41 / 74.86 ms | 10 |
| ex_0009 / Lite | 4,700 | 100% | 14.94 / 37.38 ms | 47 |
| ex_0010 / Lite | 4,775 | 97.8% | 13.77 / 31.75 ms | 11 |

三段公开视频共 14,349 帧。视频没有人工逐次计数真值，因此上述数据只能证明姿态推理链路运行过，不能据此报告动作计数准确率。

测试进程峰值 RSS 为 266.2MB，包含 Python、OpenCV 和推理运行时，但不包含完整整机操作系统、课程播放器、UI、缓存和其他服务的资源占用。

### 5.4 重要负面发现

同一段视频，在模型和规则阈值变化后，计数结果明显变化。例如 ex_0006：

- Lite：朴素阈值计数 50 次；加入平滑和驻留后 20 次；调整阈值后 24 次；
- Full：对应结果为 28、10、14 次。

没有人工标注的真实次数，无法判断哪个结果正确。这说明动作评价的核心风险不是单纯算力，而是关键点稳定性、机位、规则标定和真实样本评测。

DSH 报告中部分“最快轮次”数字缺少对应原始 JSON；RTMPose 的 7.98ms 也尚无独立原始结果。本报告不将这些数字作为验收承诺。

## 6. 推荐架构：C-lite 混合方案

**端侧实时链路：**

摄像头 → MediaPipe Lite / Full → 关键点置信度与平滑 → 当前课程动作规则 → 次数、幅度、节奏和有限提示 → 屏幕反馈。

**服务端课程链路：**

课程目录与视频 → 时间轴/动作片段 → 参考姿态提取与人工复核 → 版本化动作模板 → 下发终端。

服务端主要处理非实时的课程解析、模板管理、版本同步和设备运维。默认不持续上传用户视频逐帧推理。

| 方案 | 结论 | 风险 |
|---|---|---|
| 完全本地 | 可行，适合隐私与实时闭环 | 目标硬件性能、升级和适配 |
| 全云实时 | 不作为首选 | QPS、带宽、网络时延、持续费用和视频隐私 |
| C-lite 混合 | 当前推荐 | 课程模板质量、终端适配和同步机制 |

Web/WASM/WebGL/WebGPU 可以作为浏览器兼容性对照，但低端 Android WebView 的持续性能尚无目标设备实测。不要因桌面浏览器运行成功，就承诺所有廉价终端都能运行。

## 7. 硬件选型原则

| 候选档位 | 定位 | 必须验证 |
|---|---|---|
| 四核 ARM + 2GB RAM | 最低成本候选 | 系统、课程播放、相机、推理并发时的内存和延迟 |
| 四核 ARM + 4GB RAM | 更宽裕候选 | 整机长稳、温升和成本 |
| ARM + GPU | 可选加速 | 驱动、delegate、实际推理后端 |
| ARM + NPU | 增强型候选 | 模型转换、量化精度、SDK 许可、BOM |
| M2 / 普通 PC | POC 与开发设备 | 不能替代量产硬件验收 |

NPU TOPS 或厂商纯模型 benchmark 不能直接换算为完整产品 FPS。G2 必须使用新采购的参考主板和摄像头，联合验证课程播放、摄像头采集、推理和 UI 并发。

## 8. 第三方课程服务商必须提供什么

至少索取：

1. 课程目录与课程 ID；
2. 10–20 节可合法使用的样课；
3. 动作名称、动作 ID、动作起止时间轴；
4. 教学示范片段和推荐拍摄视角；
5. 动作变式、器械要求及适用说明；
6. 视频访问、播放和缓存方式；
7. 允许进行姿态提取、动作分析、生成衍生模板的书面授权；
8. 课程或动作变更、下架、授权终止通知机制。

播放课程的授权不自动包含视频分析、骨架提取或衍生模板的权利。如果服务商只有视频，没有动作时间轴，则需要增加离线切分、动作归类和人工复核，成本会相应增加。

## 9. G1 专项 POC：42 人日估算

仅验证深蹲、开合跳、侧平举，不做完整产品和量产硬件。

| 工作包 | 内容 | 人日 |
|---|---|---:|
| P0 | 环境搭建、模型冒烟、统一姿态契约 | 3 |
| P1 | 摄像头/视频采集与时间戳 | 3 |
| P2 | 骨架归一化、平滑、置信度门控 | 4 |
| P3 | 深蹲状态机与几何检查 | 5 |
| P4 | 开合跳、侧平举规则 | 6 |
| P5 | 样本采集、双人标注、争议裁决 | 8 |
| P6 | 分层评测、延迟、混淆矩阵 | 4 |
| P7 | 骨架叠加、角度曲线、事件回放 | 4 |
| P8 | Lite / Full / RTMPose 对照 | 3 |
| P9 | 总结与 Go / No-Go | 2 |
| **合计** |  | **42** |

建议角色：视觉/算法工程师 1 人、前端或工具工程师 1 人、QA 0.5 人、产品 0.2 人，运动专业顾问阶段性参与。42 人日是 DSH 估算，不是已落实排期或合同报价。

### 样本与验收

- 96 段常规视频 + 20 段边界样本，需建立人工逐次计数真值；
- 参与者与视频来源隔离调参集和独立盲测集；
- 建议每个动作至少 80% 测试片段完全计数正确，平均每段误差不超过 1 次；
- 记录误计、漏计、拒判比例、p50/p95 延迟、关键点缺失率和机位条件；
- 规则需由运动专业人员复核；
- 以上均为拟议验收门槛，当前尚未通过。

G1 的动作结果协议保留 model_version、rule_version、rep_count、metrics、form_flags、confidence、verdict 和拒判原因。score 在 G1 固定为 null。

## 10. 投入与预算边界

按每人日综合成本 1,000–2,000 元做敏感性估算，42 人日人工约 4.2–8.4 万元；另需考虑运动顾问、测试参与者、样本授权、摄像头/支架、设备、税费及管理成本。正式预算需财务和采购按公司真实成本替换。

此前 v0.3 的 252 人日、约 48.9 万元，是覆盖更大范围工程样机和试用的历史示意模型。它与本次 42 人日专项 POC 的范围不同，不能相加，也不能用来承诺整机研发总价。

## 11. Go / No-Go 决策门槛

- **G0 前置资料**：未取得服务商样课、动作资料和授权，不启动课程适配开发；未确定预算上限，不启动付费采购。
- **G1 算法 POC**：无法提供人工真值、三个动作未达到约定计数门槛、拒判机制不可靠或延迟不可接受，暂停 G2。
- **G2 新硬件样机**：只在 G1 通过后采购新参考主板和摄像头；若无法完成课程播放—取景—计数—反馈—报告闭环，暂停 G3。
- **G3 小范围试用**：未完成真实用户、长稳、温升、遮挡、断网、隐私和经济性验证，不进入量产承诺。
- **G4 量产**：单独核算 BOM、ODM NRE、开模、认证、课程授权、售后、OTA 和长期运维。

## 12. 管理层需要先决定的事项

1. 产品面向家庭、酒店还是健身房？目标售价、出货量和整机 BOM 上限是什么？
2. 服务商能提供什么课程资料和授权？指定商务/产品对接人。
3. 是否批准 42 人日专项 POC？预算上限、负责人和验收责任人是谁？
4. 是否接受首期只做三动作计数、幅度、节奏和有限提示，不承诺百分制评分？
5. G1 通过后，是否再进入全新硬件样机阶段？
